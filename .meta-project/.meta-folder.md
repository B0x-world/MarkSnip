# `.meta-project/`

This folder is **our** project-management material. It is not GitHub Issues, GitHub Projects, or anything the GitHub UI reads.

Use it for plans, decision records, status/handover notes, change proposals, release checklists, and risks that we want in git next to the code.

## How templates are used

1. Copy a file from `templates/` into a working folder under `.meta-project/` (for example `.meta-project/records/`).
2. Rename it with a new number and a concrete subject. Keep the `NNN-domain-subject-type.md` shape.
3. Fill in the YAML front matter. Replace `{{placeholder}}` values. Do not delete required fields.
4. Write the body from the template headings. Delete only sections that truly do not apply, and say why in `related` or the body.

Do not edit the templates in place to record a real plan or decision. Templates stay generic.

## Naming convention

Working files and templates use:

```text
NNN-domain-subject-type.md
```

- `NNN` is a three-digit zero-padded number (`001`, `002`, …).
- `domain` is a lowercase kebab-case area (`project`, `release`, `ci`, `safari`).
- `subject` is a lowercase kebab-case topic (`plan`, `file-metadata`, `macos-jobs`).
- `type` matches the document kind (`plan`, `decision`, `status`, `change-proposal`, `checklist`, `risk`, `spec`).

Examples: `001-project-plan-template.md`, `014-release-5-3-0-checklist.md`.

## Front matter

Every file in this folder, including this one and every template, starts with YAML front matter. The same field set is defined for all file artifacts in [001-project-file-metadata-spec.md](specs/001-project-file-metadata-spec.md).

| Field | Required | Allowed values |
| --- | --- | --- |
| `id` | yes | Document id, usually `{{NNN}}-{{domain}}-{{subject}}-{{type}}` until filled |
| `type` | yes | `plan` \| `decision` \| `status` \| `change-proposal` \| `checklist` \| `risk` \| `spec` \| `ci` \| `policy` \| `code` \| `form` |
| `domain` | yes | lowercase kebab-case |
| `subject` | yes | lowercase kebab-case |
| `status` | yes | `draft` \| `proposed` \| `adopted` \| `superseded` \| `deprecated` |
| `owner` | yes | person or team; empty string is allowed |
| `created` | yes | ISO date `YYYY-MM-DD` or `{{YYYY-MM-DD}}` |
| `updated` | yes | ISO date `YYYY-MM-DD` or `{{YYYY-MM-DD}}` |
| `related` | yes | list of ids or paths |
| `tags` | yes | list of lowercase kebab-case tags |
| `usage` | yes | `source` \| `test` \| `config` \| `workflow` \| `doc` \| `template` \| `script` \| `asset` |
| `template_version` | no | integer, used on templates |

Enums are lowercase. Dates are ISO-8601 calendar dates. Use `{{placeholder}}` only on fields that still need a real value.
